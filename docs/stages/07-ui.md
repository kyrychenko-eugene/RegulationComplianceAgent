# Stage 7 — UI: Run, History, Rules

Block: D. UI · Status: done

## Goal
A minimal but informative Streamlit UI that is a thin layer over `agent.check()`, `runs.jsonl` and `rules.json` — no business logic.

## Depends on
Stage 4 (and stage 6 for judge data, optional). Spec §9.

## Produces
- `ui/app.py`, `ui/run_tab.py`, `ui/history_tab.py`, `ui/rules_tab.py`.
- `examples/runs.sample.jsonl` (2–3 real runs) for the empty-history fallback.

## Scope
- **Run**: text area + button → overall verdict, summary, input with highlighted `span`s, one card per rule (verdict, severity, `source_ref`, reasoning, quote / omission note).
- **History**: runs from `runs.jsonl`, falling back to `examples/runs.sample.jsonl` labelled "example"; drill-down to a run; analytics — verdict distribution, unclear rate by reason, avg/max latency, tokens, cost, cache hit rate, judge agree/partial/disagree share, most-missed rules.
- **Rules**: approved rules (source_ref, quote, check, scope, severity, tags, critic scores, attempts), rejected rules with reasons, dropped provisions with rationale.
- Errors from `agent.check()` are displayed, never crash the app.

## Out of scope
Authentication, styling beyond Streamlit defaults, editing rules from the UI.

## Done when
- `streamlit run ui/app.py` works on a fresh clone with no own runs (sample history shown).
- Running the reference case shows FAIL with highlighted quotes.
- `ui/` imports only the public agent function and reads files; deleting `ui/` breaks nothing else.
- Time spent noted in `NOTES.md` (budget 30–40 min).
